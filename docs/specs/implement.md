# Approved implementation recipe

The Matt bundle's explicit `implement` entrypoint adapts upstream implement into
one bounded implementation request. Adaptive Goal owns native continuation and
acceptance; the recipe adds no controller or durable workflow state.

## Invariants

IMP-C1: Accept an approved specification or unambiguous ticket through the
configured provider. Preserve its acceptance, constraints, readiness evidence,
existing work, agreed test seams and inherited permissions. Approval is not a
readiness assessment. Reuse applicable assessment evidence; leave readiness
selection to Adaptive Goal. Confirm only genuinely new or changed seams before
writing their tests; do not reopen already settled choices.

IMP-C2: Explicit user invocation or preserved delegation of the same bounded
work from an explicitly invoked recipe or orchestration permits composition
with Adaptive Goal. Adapted implement remains model-invocable on both hosts so
an authorized parent can discover and invoke it through its public contract.
Its description and first workflow guard require that explicit or inherited
authority. Installation, ordinary engineering intent, an approved ticket/spec,
or an unauthorized helper naming implement supplies no invocation authority;
stop before provider discovery or effects when that authority is absent.
Read Adaptive Goal's exact host-advertised public
contract and give it the bounded request. Continue a matching existing native
main-thread goal rather than replacing it or creating a worker-owned goal.
When implement is a bounded implementation assignment from that owner, return
assignment evidence to it without invoking orchestration or independent
assessment again. Keep the caller's authority and acceptance owner unchanged.

IMP-C3: Bind the selected Matt TDD, independent Review, Git commit capability and
principles-first approach by public host-visible intent and exact advertised
instructions. Preserve provider prerequisites, effects, evidence and refusals.
No sibling installation search, central registry, copied provider internals or
raw-tool bypass may substitute for a required unavailable/refused provider.
Missing orchestration blocks standalone execution; missing a required capability
blocks its dependent work. Return the concrete gap to the same owner.

IMP-C4: Default to one local commit after current required checks and acceptance
and independent Review evidence. Honor an inherited no-commit or narrower scope.
Push and PR each need explicit or inherited publication authority. A local
implementation request supplies neither; never expand to tracker mutation,
merge, release or deployment. The enclosing delivery recipe retains its own
publication and CI duties.

IMP-C5: Report the actual candidate, changed files, tests and outcomes, literal
red/green evidence, provider evidence or gaps, local commit and any separately
authorized publication. Review success alone does not establish acceptance.
Adaptive Goal owns completion, repair history and evidence accounting.

## Evidence boundary

Use the approved package-copy/mount boundary and existing Sevro host-request to
observable-result fixtures. Check complete upstream support files and recorded
adaptations independently from native behavioral evidence. Cover approved
intake, inherited seams, local commit without publication, public composition,
and a missing required provider. Observe one-owner behavior through available
native evidence; unavailable observations remain gaps. Run changed behavior on
both actual hosts sequentially, classifying a failed trial before another run.
A single trial does not establish reliability. Do not duplicate Sevro or assert
recipe source wording as a substitute for behavior.
