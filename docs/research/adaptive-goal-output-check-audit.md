# Adaptive-goal output-check audit

This audit records the full adaptive-goal suite classification made for issue
#90. `Rigid` means an intentionally contracted status line, exact report
structure, command or identifier presence, or forbidden protocol token.
`Semantic` means a paraphrasable proposition graded by
`semantic_output_checks`. Repository, transcript, and external effects remain
in deterministic hidden checks and are not duplicated here.

## Replacement and removal decisions

- Completion and launch statuses now match the skill-owned leading
  `Status: complete` and `Status: launch_required` forms instead of accepting
  synonyms. Verification commands, report headings, protocol markers, and the
  skill-owned final authority sentence remain rigid because those exact forms
  are public contracts or simple identifiers.
- The authorized-publication branch, commit, push, and draft-PR positive
  patterns and their four separate failure-phrase guards became four semantic
  checks. Each proposition requires a successful report and rejects a
  contradictory failure report. Deterministic fixture checks still prove the
  actual effects.
- The broad derived-authority negative regex was removed as redundant. The
  public skill contract already requires the exact final authority sentence,
  while fixture and transcript checks prove the permitted and forbidden
  effects. The file-backed capability case uses the same contracted sentence.
- Review, readiness, decision, no-review, verification-completion, and
  observe-before-retry propositions became semantic checks. Their existing
  repository and fixture checks remain the stronger evidence for observable
  actions, ordering, counts, and outcomes.
- All migrated call and observation traces are passive files below
  `.git/fixture-state/`. They are fixture evidence only and are destroyed with
  the isolated trial repository.
