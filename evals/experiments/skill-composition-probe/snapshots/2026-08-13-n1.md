# Explicit-only skill composition snapshot — 2026-08-13

## Outcome

On the observed Claude Code and Codex versions, an explicitly invoked parent
skill could compose with a model-invocable child but could not run the same
child when the child was explicit-only. The exact sentinel context reached the
open child in both hosts and never reached the explicit-only child.

This rejects the proposed contract that a parent skill can invoke
`/adaptive-goal` or `$adaptive-goal` while `adaptive-goal` retains its
explicit-only invocation policy. A skill-body instruction does not inherit the
user's authority to explicitly invoke a second skill.

Follow-up: `adaptive-goal` removed those host controls and now uses the passing
model-invocable-child condition, with a workflow guard that accepts direct user
invocation or delegation from an explicitly invoked orchestration entrypoint.
The follow-up validation below exercises that guard.

## Conditions

Each host received the same opaque payload and hidden filesystem/output checks.
The parent was always explicitly invoked with the host's qualified syntax. The
three conditions were:

1. parent only;
2. parent plus child with `disable-model-invocation: true` and Codex
   `allow_implicit_invocation: false`; and
3. a matched parent plus child without those child invocation controls.

The two child variants have identical descriptions, workflows, and Codex UI
metadata. Only the Claude frontmatter field and Codex policy field differ.

The parent was forbidden to discover plugin storage, bypass host visibility,
or simulate the child. A successful child wrote a private sentinel whose path
and contents appeared only in the child body.

## Limitations

This is one trial per condition and establishes only the observed mechanical
boundary on the pinned host versions. The fixture isolates invocation semantics
rather than running a complete implementation goal. The adaptive follow-up
uses a decision-gated preflight, not an implementing route. These results
support the selected invocation architecture; they are not reliability or
quality estimates for either model and require multi-trial follow-up.
