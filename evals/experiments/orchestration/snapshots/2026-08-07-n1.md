# Orchestration value benchmark

Status: exploratory evidence, not an accepted architecture decision  
Run date: 2026-08-07  
Scope: one trial per task, four OSS tasks, four modes, Claude Code and Codex

## Executive conclusion

This run does not show incremental value from either Darrow orchestrator over
the direct baselines.

- **Vanilla is the strongest default.** It passed all four task contracts on
  both harnesses. On Codex it tied native-goal for judge quality while being
  slightly faster and using fewer tokens.
- **Native-goal is the only credible challenger.** It also passed all task
  contracts. It was nearly tied with vanilla on time and showed a stronger
  Claude judge-pass result, but used more tokens and cost more on Claude.
- **`darrow-goal-loop` regressed quality and efficiency.** It passed three of
  four task contracts on both harnesses, failed the Click stream-lifecycle task
  twice, took 3.2 times vanilla wall time on Codex and 2.1 times on Claude, and
  cost 2.1 times vanilla on Claude.
- **`darrow-ticket-pipeline` was the weakest condition.** It passed three of
  four tasks on Codex and two of four on Claude, took 5.1 times vanilla wall
  time on Codex and 3.4 times on Claude, used 4.0--6.3 children per task on
  average, and required human interventions.
- **Rewriting the goal-loop controller from Bash is not supported by this
  evidence.** Candidate runs lasted minutes and spent their overhead in model
  rounds and child invocations. Shell execution is too small a fraction of the
  measured wall time to plausibly reverse the result. Establish value first;
  change implementation language only for maintainability or correctness
  reasons demonstrated separately.

The appropriate next comparison is vanilla versus native-goal with at least
three trials per cell. A single trial is insufficient for a durable promotion
decision: the initial Codex/ticket-pipeline Click candidate passed before its
cell was lost to an evaluator cleanup error, while the provenance-captured
rerun failed the same task. Only the rerun is included quantitatively below.

## Qualitative judge observations

### codex / darrow-ticket-pipeline

Strengths:

- Implements instancePath clearing at parser entry and preserves undefined after successful parses.
- Correctly propagates paths through nested properties, arrays, values schemas, discriminators, and recursive refs.
- Uses existing codegen utilities for JSON Pointer escaping instead of adding ad hoc runtime logic.
- Updates the public JTDParser type and adds focused regression tests for the requested cases.
- Scope is narrow and limited to parser implementation, types, and relevant tests.

Weaknesses:

- Unknown additional-property failures still report the containing object path rather than the unexpected property path, which may be debatable for full object-property diagnostics.
- Tests do not cover additionalProperties rejection or missing required property path semantics.
- The requested behavior is not implemented: `CliRunner` still has `mix_stderr`, defaults to mixing stderr into stdout, and does not always capture stdout and stderr independently.
- `Result.output` still returns only `stdout`; there is no `Result.output_bytes` preserving chronological interleaving.
- `Result.stderr_bytes` remains optional and `Result.stderr` can still raise `ValueError` when stderr is mixed, contrary to the new contract.

### claude / darrow-ticket-pipeline

Strengths:

- Implements instancePath clearing at parser entry and preserves undefined after successful parses.
- Tracks object properties, values maps, array indexes, discriminator mappings, and recursive referenced definitions using existing JSON Pointer escaping utilities.
- Updates the public JTDParser type with instancePath.
- Adds focused regression tests for nested objects, arrays, escaped keys, refs, discriminator behavior, and success after failure.
- Diff is tightly scoped to parser implementation, type definition, and relevant tests.

Weaknesses:

- No significant weaknesses found.
- The requested behavior is not implemented: `CliRunner` still has the `mix_stderr` constructor option and defaults to mixing stderr into stdout.
- `Result.output` still returns `stdout`, and there is no `Result.output_bytes`.
- `stderr_bytes` can still be `None`, so stdout and stderr are not always captured independently.
- Existing tests still assert the old `mix_stderr` behavior instead of the new independent stream plus chronological combined output contract.

### codex / native-goal

Strengths:

- Implements instancePath reset at parser entry and leaves it undefined on successful parses.
- Tracks object properties, array indexes, values-form keys, discriminator failures, and referenced parser failures with RFC 6901 escaping via existing Ajv utilities.
- Preserves existing message and position behavior while adding instancePath alongside existing error handling.
- Public JTDParser type is updated and the diff is tightly scoped to parser code, types, and focused tests.
- Implements independent stdout and stderr byte capture while adding combined chronological output_bytes and output text decoding from that combined stream.

Weaknesses:

- Tests cover the requested main cases but do not add explicit assertions for missing required properties, additionalProperties=false failures beyond indirect behavior, or malformed JSON inside nested values.
- The implementation adds path propagation directly through parser context, which fits the existing file but slightly increases coupling in partial parser calls.
- The internal _TeeBytesIO/getvalue_copy design is a little indirect because the combined stream is retrieved through the stdout tee rather than returned explicitly from isolation, but it remains understandable and scoped.
- Regression tests cover the main contract but could be slightly more exhaustive by separately checking `>` and DEL/control edge cases.
- Tie behavior for equal-length matches is deterministic but implicit rather than documented or directly tested.

### claude / native-goal

Strengths:

- Implements instancePath propagation through nested properties, array indexes, values maps, discriminator parsing, and referenced definition parsers while preserving message/position behavior.
- Clears message, position, and instancePath at parser entry, leaving instancePath undefined after successful parses including after prior failures.
- Uses existing getErrorPath utility for RFC 6901 escaping instead of duplicating pointer escaping logic.
- Public JTDParser type is updated, and focused tests cover the core requested cases.
- Implements independent stdout and stderr capture while adding a combined output_bytes stream that preserves write order.

Weaknesses:

- The focused instancePath spec file is untracked in the working tree, so it would be easy to omit from a submitted patch even though it is present locally.
- Tests are good but do not explicitly cover disallowed additional properties or missing required properties path semantics.
- User-facing documentation beyond docstrings and release notes was not updated, so docs/testing.rst does not explain the new stdout/stderr/output behavior.
- Regression tests cover normal text interleaving and echoed stdin, but do not directly assert newline normalization or invalid-byte replacement on the new combined output property.
- Validation is implemented inline rather than as small named helpers, which is acceptable here but slightly less self-documenting.

### codex / vanilla

Strengths:

- Implements instancePath reset on every parser call and leaves it undefined after successful parses.
- Tracks nested object properties, array indexes, values schemas, discriminator failures, and referenced definitions with correct RFC 6901 escaping.
- Preserves existing message and position behavior while extending the public JTDParser type.
- Adds focused regression tests covering the requested scenarios, including success after failure.
- Implements independent stdout and stderr capture while adding combined chronological output_bytes/output semantics.

Weaknesses:

- The internal partialParse argument handling is a little brittle because it special-cases args === true for referenced parser calls, but it fits the existing parser structure and is covered by tests.
- The helper stream container is lightly custom and only tuple-compatible for stdout/stderr, which is acceptable but could be documented or typed more explicitly.
- Tests cover key behavior but do not explicitly assert that passing mix_stderr now fails as a removed constructor option.
- Tests verify TypeError class and behavior but not exact invalid-header cases exhaustively, such as DEL in relation names or angle brackets independently.
- Tests cover the core regressions but do not explicitly exercise deterministic equal-length tie behavior or mixed empty/non-empty insteadOf round trips.

### claude / vanilla

Strengths:

- Implements instancePath clearing at parser entry and preserves undefined on success after prior failure.
- Tracks nested object properties, array indexes, values maps, discriminator mapping payloads, and referenced definitions, using Ajv's existing JSON Pointer escaping helper.
- Updates the public JTDParser type.
- Adds focused regression tests for nested objects, arrays, escaped property names, values, refs, discriminator behavior, and success-after-failure.
- Removes the public mix_stderr constructor option and updates Result so stdout, stderr, and output_bytes are exposed separately.

Weaknesses:

- No material implementation weaknesses found. Some edge cases such as syntax errors while skipping non-discriminator fields are not explicitly covered, but this does not conflict with the requested schema-diagnostic behavior.
- Chronological interleaving is not preserved for unflushed direct text writes because stdout and stderr TextIOWrapper buffers are copied to the mixer only when each stream flushes. For example sys.stdout.write('o1'); sys.stderr.write('e1'); sys.stdout.write('o2'); sys.stderr.write('e2') produces output_bytes b'o1o2e1e2' instead of b'o1e1o2e2'.
- The isolation docstring says an additional output stream is returned, but the implementation still returns only two streams and recovers the mixed stream through an internal copy_to attribute.
- Tests cover click.echo interleaving, but miss direct sys.stdout/sys.stderr writes without explicit flush, which is a core stream-capture contract edge case.
- The implementation also rejects non-string targets, which is stricter than the task and could be a minor compatibility change for callers relying on string coercion, such as URL objects.

### codex / darrow-goal-loop

Strengths:

- Implements instancePath reset on parser entry and preserves undefined after successful parses.
- Propagates JSON Pointer paths through object properties, array indexes, values schemas, discriminator handling, and referenced parsers.
- Escapes JSON Pointer segments correctly for ~ and /.
- Updates the public JTDParser type and keeps existing message/position behavior intact.
- Changes are tightly scoped to parser compilation, public typing, and focused tests.

Weaknesses:

- Path propagation adds generated local variables at each segment, which is clear enough but slightly increases generated-code noise.
- Tests are focused and meaningful, though they do not exhaustively cover every discriminator/ref shape visible in the implementation.
- The deterministic hidden stream interleaving contract failed, which is a material defect for the central requested behavior: Result.output/output_bytes must preserve exact chronological write order across stdout, stderr, and echoed stdin.
- The added tests cover simple interleaving but did not catch the hidden ordering case, so the regression coverage is incomplete.
- Public documentation and type-facing notes are minimal; output_bytes lacks a version marker and the isolation return shape change is not clearly documented.

### claude / darrow-goal-loop

Strengths:

- Adds instancePath reset at parser entry and sets it on all normal parsingError paths while preserving message and position.
- Uses existing getErrorPath helper, so object keys are escaped per RFC 6901 and array indexes are formatted consistently with Ajv internals.
- Handles nested properties, arrays, values schemas, discriminator branch properties, and recursive ref parser failures, including clearing stale paths after later success.
- Public JTDParser type is updated and the diff is tightly scoped.
- Focused upstream tests reportedly pass.

Weaknesses:

- A discriminator tag value that is present but not a string appears to fail at the containing object path rather than the discriminator property path, which is a minor uncovered edge case.
- Tests are focused and useful, but do not cover malformed/non-string discriminator tag values or recursive refs beyond a simple referenced schema.
- No implementation of the requested behavior is present in the current final diff; the working tree diff is empty.
- `CliRunner` still exposes and uses the `mix_stderr` constructor option, contrary to the task.
- `Result.output` still aliases `stdout`, so it cannot preserve chronological stdout/stderr interleaving.

## Interpretation limits

- `unknown` cost is intentional when a harness does not report actual provider cost; token counts remain available when the harness reports them.
- Compare modes primarily within the same harness/model/effort block. Cross-harness differences also include model and CLI effects.
- Setup and dependency installation occur before candidate timing. Judge work is measured separately.
- Protocol-only failures indicate missing evaluation records, not a failed codebase contract; task pass and judge quality remain separately visible.
- Human interventions are explicit stops for human decisions or authority, not ordinary model reasoning.
