# Current Codex orchestration benchmark

Status: exploratory N=1 first pass; 16 attempts, 15 assessed, one host-limited.

The implementation comparison passed all four tasks in both conditions. Adaptive
Goal averaged 561.8 seconds against vanilla's 132.2 seconds: 4.25 times the
candidate wall time, with no difference in the observed acceptance pass rate.
This run does not establish a code-quality advantage or reliable pass rates.
Both vanilla conditions required testing and same-context self-review, with
fixes as needed. Darrow adds independent review and bounded repair when selected.
These are different assurance processes; the timing and usage comparisons cover
the whole workflow rather than an isolated implementation or review phase.
Both full-delivery conditions include the Git workflow, PR publication and CI.
The comparison does not hold the assurance process constant, so higher resource
use cannot be attributed solely to orchestration mechanics or establish that
the additional assurance is unnecessary.
Full delivery passed all four vanilla trials and all three assessed Ticket to PR
trials. Click recipe delivery could not be assessed because its event stream
exceeded the evaluator's limit. Across the three assessed delivery pairs, the
recipe took 3.22 times vanilla's candidate wall time. Resolve that host limit
before retrying Click or replicating the comparison.

## Conditions

The main thread uses `gpt-6.1-sol/medium`, Codex CLI 0.165.0 through its native
app-server transport, and Sevro 1.1.1. Adaptive Goal 0.27.1 owns the native goal
in the main thread and selects implementation placement through its current
policy. The condition does not force a separate goal owner or fixed children.
Ticket to PR 0.6.3 delegates delivery to that same design.

Each task/condition has one trial. There are two separate comparisons:

- Implementation: vanilla versus Adaptive Goal, without commits or publication.
- Delivery: vanilla versus Ticket to PR, including a ticket branch, TDD,
  verification, commits, one ready PR, required CI and a final handover.

Vanilla receives the same task requirements and mounts no Darrow plugins.
Candidate conditions mount the current capabilities and applicable Review, TDD
and Tickets reminders. These are workflow comparisons, not skill-only ablations.
Complete host receipts show no native goal events or accepted subagent spawns
in any of the eight vanilla controls.

Including its host-limited attempt, the recipe spent 802.6 seconds per attempted
task on average. This attempted-duration mean is separate from completed-trial
latency and does not supply a missing Click correctness result.

Delivery uses a real local bare Git remote, a simulated forge and an actual
focused upstream check in Sevro's credential-free isolated shell grader. The
oracle requires the clean final checkout, pushed branch and open PR to agree,
with a genuine successful CI receipt for that exact commit. No real GitHub PR is
published. This does not measure hosted CI queues or GitHub network reliability.

Two earlier completed Express delivery attempts passed their code checks but
could not complete CI because of harness defects. They are excluded from product
pass rates: the first nested fixture could not clone the active workspace; the
second copied dependency executables with symlinks into the protected original
workspace. The repair materializes the published branch and preserves relative
dependency symlinks. Deterministic tests cover this path, and a no-model check
on the retained Express implementation passed before the valid control rerun.
Earlier preparation and setup failures are also excluded; their artifacts remain
available beside the valid runs.

Adaptive Goal used at least 12.71× the tokens and 5.12× the estimated model cost
of vanilla across the four implementation tasks. The three assessed delivery
pairs used 7.78× the tokens and 5.23× the estimated cost with Ticket to PR.
Cached input dominates the workflow totals, so token growth is larger than
estimated dollar growth. These totals include the extra coordination, independent
assurance and repair where selected; their incremental value is not isolated.

Each distinct session contributes its final cumulative counters once. Reasoning
is included in output and cached input is included in input. Both Click workflow
transcript bundles are partial, leaving their usage as observed lower bounds;
the implementation task itself passed. Other bundles are complete. Across all
four recipe delivery attempts, including the interrupted Click attempt, mean
observed usage is at least 8,225,009 tokens and $1.506 API-equivalent cost.

The normalization uses [official OpenAI Standard API pricing](https://developers.openai.com/api/docs/pricing)
read on 2026-10-30: per million uncached input / cached input / output tokens,
Sol 6.1 costs $2 / $0.10 / $10 and Luna 6 costs $0.10 / $0.01 / $0.50. Every
retained request was below 272K input tokens (maximum 100,787) and recorded zero
cache writes. Sessions are priced on their observed model. These estimates do
not establish actual Codex subscription charges; actual monetary cost is unknown.

Across the three assessed recipe deliveries, mean estimated cost consists of
$0.636 for the main thread, $0.452 for verification/review coordinators, $0.167
for the two independent review readers, and $0.008 for the Luna implementation
delegate averaged across all three tasks. Only go-git selected that Luna delegate;
the other two recipe traces used Sol throughout. Over 99% of the estimated
recipe spend was therefore on Sol. The main thread averaged 52 model requests
with 66.2K input tokens per request, versus vanilla's 20.3 requests with 39.1K.
These observations explain where spend accumulated; they do not isolate which
coordination or assurance work could be removed while preserving its benefits.

## Historical comparison

The [August 7 snapshot](2026-08-07-n1.md) recorded Codex vanilla at 4/4 and 216.5
seconds mean, and ticket-pipeline at 3/4 and 1110.4 seconds mean. Those runs used
`gpt-5.5/medium`, Codex CLI 0.145.0, an older evaluator and an advisory judge.
They are historical context, not a controlled estimate of the current design's
effect. The old pipeline scope excluded publication, so it is not a full-delivery
baseline.

The four engineering prompts and upstream revisions match that historical run.
Current canonical hidden checks are used verbatim. Since August, Click gained an
unflushed-write check, Ajv gained malformed-value path checks, and go-git gained
deterministic serialization coverage and a public configuration seam in place
of a private helper assertion. Inspection guidance and Go cache setup also
changed. These grading differences accompany the model and evaluator changes.
