# Isolated ticket workers

Select read-only when fresh ticket context repays handoff/rereading/integration,
including sequentially on the same route. Record basis; size/count alone is insufficient.

## Preflight

1. **Scope.** Bind authoritative specification, finite ticket set, dependencies,
   criteria, shared decisions, preserved work/effects. Read/list capabilities prove
   no complete discovery. Missing decisions/evidence/prerequisites stop affected work.
2. **Assurance.** Prebind compatible independent Review of the complete specification
   at every risk level. Missing assurance stops activation/worker effects. Acceptance
   accounting stays here.
3. **Authority.** Require explicit user/preserved caller authority for worker
   branches/worktrees/commits/integration; preserve the delivery checkout. Prebind
   branch/worktree creation separately from delivery-branch discovery/reuse.
   `create-branch` owns ticket naming; invented names cannot justify
   `prepare-task-branch`. Existing delivery branches cannot satisfy fresh-worker
   requests. Create from verified integration branch/pinned `HEAD`, using current-HEAD
   default. `--from` requires a user-named base permitted by the public contract.
4. **Commits.** Prebind the public commit skill; reconcile message rules. Give each
   fresh worker exact name/reference; require invocation for every implementation/
   repair commit. Focused checks permit intermediate commits before final assurance,
   without bypassing bindings/message rules/refusals. Raw Git cannot substitute.

## Dispatch

- **Parallelism.** Require substantial independent tickets, disjoint files, settled
  interfaces, focused checks and host capacity. Keep overlap/coupling sequential.
- **Snapshot.** Pin one integration branch/commit per parallel batch. Verify tip
  before each allocation; changed tip stops allocation. Await all before integration/
  next batch. Land serially; dispatch dependents only after prerequisites land.
  Worker completion/tracker closure cannot unblock dependencies.
- **Handoff.** Distinct branch/worktree per worker; section 7's assignment plus
  absolute checkout/pinned commit/specification/interfaces. Preserve readiness and
  pre/post-edit public-seam evidence. Retain worker identity for repairs.
  Main thread owns integration/assessments/repairs/publication. Workers get no
  Adaptive Goal/goal control, scope expansion, PR publication or tracker changes.
  Require ordered full commit IDs, files, actual checks/gaps as intermediate results.

## Integration

1. **Wait.** Use native controls. Blocker/refusal/unavailable required checks stops
   affected work/repairs. Preserve the prerequisite; never shell-poll settled workers
   for commits or repeat denied actions.
2. **Land.** After all implementation settles, cherry-pick commits serially, without
   merge/fast-forward. Before each, verify expected integration branch/tip and exact
   commit/ancestry/files against assignment; confirm landed tip.
3. **Conflict.** Changed tip/missing prerequisite/conflict stops landing. Return
   state to retained worker. Preserve user edits/unrelated worktrees; no reset,
   forced refs or silent out-of-scope resolution. Resume with clear candidate and
   authorized resolution.
4. **Accept.** Pass combined checks; run bound Review once for the full specification.
   Map every criterion to current evidence/gaps, including unavailable services/
   fixtures/skipped checks. Avoid per-ticket assessment cycles. Return findings and
   integration state to producing workers; integrate repairs, refresh invalidated
   combined checks and obtain closed follow-up. Section 7/lifecycle own the shared
   allowance. Authorized publication produces one combined PR after acceptance.
