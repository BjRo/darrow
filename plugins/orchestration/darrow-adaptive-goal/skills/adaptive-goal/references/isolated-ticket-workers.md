# Isolated ticket workers

Select during read-only preflight when fresh ticket context repays handoff,
rereading and integration overhead, even sequentially on the same route.
Record the basis; size or ticket count alone is insufficient.

## Bind scope and effects

Bind the authoritative specification, explicit finite ticket set, dependencies,
criteria, shared decisions, preserved work and allowed effects. Read/list
capabilities do not establish complete discovery. Missing decisions, evidence or
prerequisites stop affected work.

Require final independent Review of the complete specification at every risk
level. Bind its compatible public skill before goal activation or worker effects;
missing assurance stops launch. Keep acceptance accounting in the main thread.

Worker branches, linked worktrees, local commits and integration require explicit
user or preserved caller authority. Keep the delivery checkout. Prebind new-branch
and linked-worktree creation separately from delivery-branch discovery/reuse.
Darrow Git's `create-branch` owns naming from ticket work; constructing a name
cannot turn creation into `prepare-task-branch`. An existing delivery branch
cannot satisfy a fresh worker request. Invoke creation from the integration
checkout after verifying its branch and pinned `HEAD`, using its current-HEAD
default. Pass `--from` only for a user-named base permitted by that public contract.

Prebind the public commit skill. Every fresh worker receives its exact advertised
name and instruction reference and must invoke it for every implementation or
repair commit. Reconcile repository/provider message rules before dispatch.
Intermediate commits follow focused checks and bypass only final-candidate
assurance, never bindings, message rules or refusals. Raw Git cannot substitute.

## Dispatch bounded batches

Concurrency requires substantial independent tickets, disjoint owned files,
settled interfaces, runnable focused checks and host capacity. Keep overlapping
or coupled tickets sequential; fresh context alone does not justify concurrency.

Pin one integration branch/commit for the entire parallel batch. Verify its tip
before each allocation; all workers start there. A changed tip stops allocation
until the common base is clear. Wait for every batch assignment before integration
or next-batch dispatch. Land serially, then dispatch dependents from the updated
integration branch after prerequisite commits land. Worker completion or tracker
closure cannot unblock dependencies.

Give each worker a distinct branch/worktree and self-contained section 7 assignment
with absolute checkout path, pinned commit, specification, interfaces, owned files,
permitted effects, preserved work, exact skills and checks. Preserve readiness and
required public-seam pre/post-edit evidence. Retain its host identity for repairs.
The main thread owns integration, verification scheduling, repairs and publication.
Workers cannot invoke Adaptive Goal, create goals, coordinate assessments, expand
scope, publish PRs or change tracker state. Require ordered full commit IDs,
changed files, actual checks and gaps; these commits are intermediate results.

## Integrate

Use native wait/follow-up controls. A returned blocker, refusal or unavailable
required check stops affected work, including repairs. Preserve it and report the
prerequisite needed to resume. Do not shell-poll a settled worker for commits or
repeat denied actions.

After all implementation settles, cherry-pick returned commits serially onto the
integration branch, without merges or fast-forwards. Before each commit, verify
branch/tip against the expected state and inspect the exact commit, ancestry and
files against its assignment. Confirm the landed tip before continuing.

A changed tip, missing prerequisite or conflict stops landing. Return concrete
state to the retained worker. Preserve user edits and unrelated worktrees; no
reset, forced refs or silent out-of-scope resolution. Resume only with a clear
candidate and authorized resolution.

After integration, pass combined checks and run bound independent Review once
for the complete specification. Map every criterion to current evidence/gaps;
missing services/fixtures or skipped required checks remain gaps. Avoid per-ticket
assessment cycles. Send findings and current integration state to the producing
worker, integrate repairs and refresh invalidated combined checks before closed
follow-up. Section 7 and the lifecycle own the shared repair allowance.
Authorized publication produces one combined PR under the normal acceptance gates.
