# Host and authority compatibility

Use the skill advertised by the active host. On Claude Code, invoke an advertised
skill through its native Skill facility. On Codex, read the advertised SKILL.md
through the supported reader and follow it; do not invent a Claude Skill tool.
Explicit user entrypoints are `$darrow-matt-pocock:<skill>` on Codex and
`/darrow-matt-pocock:<skill>` on Claude Code. Preserve explicit-only metadata for
upstream entrypoints. A supporting reference does not authorize another workflow's
external effects.

Use the host's advertised delegation tools for bounded fresh-context work.
Carry the question, required output, relevant context and inherited authority.
If the required delegation facility is unavailable, report the limitation;
do not claim a fresh or independent agent ran. Supporting skills in this bundle
are reached through host discovery. Never read another plugin's files or add a
second capability registry. Independent review uses advertised review intent,
such as Darrow Review, and remains a separate authorized operation.

Before tracker work, read the project's configured provider, permissions and
label mapping. Existing provider choice takes precedence over remote-host guesses.
Missing configuration requires explicit setup; do not silently fall back to a
local or remote tracker. Use available native relationships and configured label
names. Do not install triage or create labels merely because a template names them.
Preserve human confirmation of new seams and ticket breakdowns.

Stay within the invocation and inherited authority. A request to draft does not
publish. A request for local implementation does not authorize push or PR creation.
Planning does not start Adaptive Goal or another orchestration owner. Prototype
capture, research branches, tracker updates, and remote changes inherit the same
limits. Report a missing permission before the affected action, while completing
already-authorized local work.
