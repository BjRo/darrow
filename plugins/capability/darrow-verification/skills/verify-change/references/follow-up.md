# Targeted follow-up handoff

Use this branch for one fresh assessment of owner-attempted repairs. Return
finding states to the owner; do not count, allocate or spend its repair budget.
An assessment invocation is not an owner repair attempt. Preserve supplied repair
history without inventing attempt counts or remaining allowances.

## Bind the closed history

Require the original objective, criteria and constraints, plus:

- original complete findings and target; each finding's stable identity,
  provider/axis, severity, blocking/advisory disposition, location, source and
  original evidence;
- immediately prior and current candidate identities, scope/base and intervening
  target history; explicitly identify the first follow-up when there is no
  previous follow-up;
- owner-attempted repairs and changed-content evidence associated with original
  findings; every original blocker has an attempted or unavailable state;
- complete previous follow-up results and carried direct regressions, including
  their stable identities and immutable causing-original-finding identities; and
- current required checks and original/prior evidence needed for the provider
  to establish present content and direct repair causality.

Missing, contradictory or unreadable history blocks this operation. Return the
specific gap instead of starting a new comprehensive review. Provider-specific
references travel opaquely to that provider: preserve any scope artifact or prior
verification report its public contract requires. Do not parse private records
or fabricate missing artifacts. A replacement must honestly consume the retained
history without reopening the finding set or imposing another registry.

## Obtain fresh closed-set judgment

Request provider assessment of the current candidate against the original
findings, attempted repairs and direct consequences. The original finding set
stays closed except for evidenced direct repair-caused regressions. Each new
regression must name its causing original finding. Carry prior regressions under
the same identities and immutable causes; only their current states/evidence
may change. Unrelated observations cannot enter this operation or extend a budget.
The causal key identifies the attempted repair that introduced the failure;
the regression need not violate the same criterion as that original finding.
If the repair's causal relationship is unsupported, report that evidence gap
instead of calling the regression both direct and unrelated to the repair.

Preserve the provider's actual judgments: resolved, materially improved but
unresolved, unchanged, or unavailable. Provider vocabulary may differ. A new
direct regression can justify progress while remaining blocking; unchanged
regression evidence after an owner attempt is no-progress. Repeated or oscillating
target/failure evidence is not progress merely because another assessment ran.

Observed inherited conversation context is a freshness gap even if the provider
calls its reader fresh. Missing fresh observation or unsuccessful/unavailable
required checks prevents clear. Author assertions cannot clear findings.
Advisories remain nonblocking even when unattempted or unresolved.

## Return the finding states visibly

The final response itself must include the following meanings for **every**
original finding and carried/new direct regression. Use a compact table unless
the caller requested another presentation. This organizes verification's
outward handoff; it does not dictate the provider's report format.

| Identity             | Provider / original axis | Original disposition | Current state and evidence | Causing original identity                              |
| -------------------- | ------------------------ | -------------------- | -------------------------- | ------------------------------------------------------ |
| Retained finding key | Retained provenance      | Blocking or advisory | Provider judgment          | Regression's evidenced cause, otherwise not applicable |

A resolved original blocker still needs its original axis and blocking
disposition. “F is resolved” or a criterion status alone loses that history.
An unattempted advisory must be explicitly visible and nonblocking. A direct
regression must explicitly name the original finding whose repair caused it;
“caused by the repair” alone loses the causal key. Use actual provider identities
and judgments, never invented substitutes.

Linking the complete provider report does not replace these visible finding
states. Include both the outward states and the readable absolute report path
(or its complete inline result). Check the final response itself, not only the
linked artifact, before returning it.

Alongside those states, preserve original/prior/current targets, attempted-repair
and prior-result references, current checks, criterion-by-criterion evidence and
limitations, the provider's native outcome and one aggregate conclusion.
Unchanged criteria may retain evidence only when it demonstrably applies to
the current candidate. An unrelated unsupported criterion is an evidence gap,
not an invented new review finding.

Clear ends this operation. Progress returns evidence for the owner's decision;
it neither authorizes another attempt nor assigns a remaining budget. For
no-progress, replace the generic "smallest next action" section with a stop
reason: the unchanged evidence does not support another repair attempt. Keep
expected versus observed values in the finding evidence, but do not turn the
expected value into an instruction to edit it. Do not append a proposed fix,
an edit followed by another verification request, or conditional repair advice
such as "if authorized." This no-progress return rule overrides the generic
next-action request in the main workflow; saying that the owner decides does
not make an appended repair recipe permissible. Include the absolute report
path. For blocked, identify the smallest missing evidence. The active
owner alone implements, repairs and decides continuation under its shared limits.
