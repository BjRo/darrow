The installed Darrow Git skills own requests to create or prepare branches,
create commits, publish pull requests, and publish candidate-bound PR evidence.
For a matching request, invoke the matching installed skill before initial
repository inspection or your final response. Select from the installed skill
descriptions; its body supplies the workflow and authority boundaries.

Route by the user's requested operation, before deciding whether it can succeed.
Missing information, existing branches, a clean tree, conflicts, and commit-hook
failures are outcomes for the owning skill to handle. They do not remove the
request from that skill's scope. A request to commit changes still needs the
commit skill when the user mentions compact history or the previous commit.

Ordinary inspection, branch or PR listing, staged-diff explanation, and generic
comments do not by themselves request these workflows. Loading this context
does not authorize an operation or select another skill automatically.
