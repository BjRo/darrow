# Darrow Ticket to PR

`ticket-to-pr` is an explicitly invoked task recipe for turning one ready,
authoritative ticket in the current repository into exactly one verified pull
request. It preserves the active provider's opaque ticket token in any derived
branch and safely prepares that branch before readiness so automatic
branch-inferred observability attributes the complete delivery flow to the
ticket. The recipe owns ticket intake, readiness interaction, and the bounded
branch, commit, non-force push, and pull-request authority envelope. A
compatible adaptive native-goal capability owns execution, verification,
feedback, and completion.

When that owner blocks, an unambiguous response in the same host thread resumes
the same delivery, objective, and owner. A retry is one attempt of the exact
failed operation and observes ambiguous publication first; an explicit waiver
can skip only a discretionary Darrow gate. Repository policy, safety,
authorization, and truthful pull-request completion remain mandatory. A fresh
conversation still requires explicit `ticket-to-pr` invocation, though it may
reuse correlated repository and pull-request state.

The recipe never creates a controller, retry runtime, ledger, status file,
worktree, merge, release, deployment, or ticket mutation.
